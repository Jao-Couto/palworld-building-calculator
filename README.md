# Palworld Building Calculator

A resource/recipe calculator for Palworld 1.0, built from data exported directly from the game (DataTables, Blueprints, and localization files). Given an item, structure, or quantity, it should compute the raw materials needed, recursively expanding any craftable ingredients, and consolidate totals across multiple targets.

This repository currently focuses on preparing and validating the underlying data before the calculator itself is built.

## Status

Data preparation in progress. What's done so far:

- Verified that the exported game data (`data/`, gitignored — see below) covers items, recipes, structures, technology unlocks, and localization, per the [data export specification](#data-export-specification) below.
- Reconstructed the item → crafting station link, which is **not** present in `DT_ItemRecipeDataTable_Common` itself. The real link lives in each structure's Blueprint file, in a `PalMapObjectItemConverterParameterComponent` (`TargetTypesA` / `TargetTypesB` / `TargetRankMax`). See [scripts/generate_bench_recipes.py](scripts/generate_bench_recipes.py).
- Identified ~39 items with a recipe entry that don't resolve to any crafting station — these turned out to be boss drops, event/NPC rewards, and Pal partner-skill unlocks rather than player-craftable items. Documented as a possible future feature in [Future feature: special-origin items](#future-feature-special-origin-items) below.

Not started yet: the actual calculator (data models, recursive recipe expansion, UI).

## Data

Game data lives in `data/` and is **not committed** to this repository (see `.gitignore`) — it must be exported locally from the game files (e.g. with FModel/UAssetGUI) following [Especificacao_Calculadora_Palworld.md](Especificacao_Calculadora_Palworld.md). Expected layout:

```
data/
└── Pal/Content/
    ├── Pal/DataTable/Item/          # item + recipe DataTables
    ├── Pal/DataTable/MapObject/     # buildable structures
    ├── Pal/DataTable/Technology/    # tech tree unlocks
    ├── Pal/DataAsset/Item/          # item icon references
    ├── Pal/Blueprint/MapObject/     # structure blueprints (crafting station rules)
    └── L10N/<lang>/                 # localized names/descriptions
```

Generated (derived) files, committed to the repo:

- `data/workbenches.json` — an earlier, manually-researched best-effort mapping of item categories to crafting stations (wiki-sourced, confidence-tagged). Superseded by the script below wherever it disagrees.
- `src/data/bench_recipes.json` — the real item → crafting station mapping, generated by running [scripts/generate_bench_recipes.py](scripts/generate_bench_recipes.py) against the exported data.
- `src/data/items.json` — craftable items + raw materials reachable from the recipe graph, generated by [scripts/build_items_json.py](scripts/build_items_json.py) (depends on `src/data/bench_recipes.json`).
- `src/data/buildings.json` — buildable structures and their material costs, generated by [scripts/build_buildings_json.py](scripts/build_buildings_json.py) (depends on `src/data/items.json`, to backfill any material that isn't already in it, e.g. crop seeds).

## Setup

Requires [uv](https://docs.astral.sh/uv/).

```bash
uv venv
uv sync
```

## Usage

Regenerate the derived data files from the exported game data, in this order (each depends on the previous one):

```bash
uv run python scripts/generate_bench_recipes.py
uv run python scripts/build_items_json.py
uv run python scripts/build_buildings_json.py
```

Run these from the repository root — their paths are relative to `data/` and `src/data/`.

## Data export specification

Specification for exporting only the files needed to build a recipe/structure/resource calculator.

### Required files

**1. Item recipes** — folder `Pal/Content/Pal/DataTable/Item/`, table `DT_ItemRecipeDataTable_Common`. Contains: produced item, produced quantity, ingredients, quantity per ingredient, crafting station, `WorkAmount`.

**2. Item data** — folder `Pal/Content/Pal/DataTable/Item/`, table `DT_ItemDataTable`. Contains: `ItemId`, category, weight, rarity, internal name, icon reference, localization keys.

**3. Structures** — export the whole folder (or all related DataTables): `Pal/Content/Pal/DataTable/BuildObject/`. If it doesn't exist, look for `Build`, `BuildObject`, or `Structure` instead. Needed to get: buildable structures, build recipe, required crafting station.

**4. Technology** — folder `Pal/Content/Pal/DataTable/Technology/`, tables `DT_TechnologyRecipeUnlock_Common` and (optionally) `DT_TechnologyDataTable`. Allows showing: level, required technology.

**5. Localization** — export the whole folder `Pal/Content/L10N/`. Languages: pt-BR, en, es, fr, de, ja, ko, ru, zh-Hans, etc. Used for: item names, structure names, descriptions.

**6. Icons** — export `Pal/Content/Pal/Texture/UI/InventoryItemIcon/` as PNG. Each item should have an `ItemId` and an icon path.

### Expected data model

**Item:** `ItemId`, name, category, weight, icon, description, recipe (optional), craftable (boolean).

**Recipe:** product, produced quantity, ingredients[], crafting station, time, `WorkAmount`.

**Ingredient:** `ItemId`, quantity.

### Features

Search item; search structure; select quantity; sum ingredients; recursively expand recipes; compute base raw materials; show icons; switch language; filter by category.

### Algorithm

1. Load all items.
2. Load all recipes.
3. Build an index by `ItemId`.
4. When an item is selected: find its recipe, multiply by quantity, recursively expand craftable ingredients (optional).
5. Consolidate repeated ingredients.
6. Display the final result.

### Suggested data layout

```
data/
├── items.json
├── recipes.json
├── technologies.json
├── localization/
└── icons/
```

### Expected outcome

The application should be able to calculate: immediate resources to craft an item; immediate resources to build structures; base resources (recursive expansion); consolidated totals across multiple items and structures.

## Future feature: special-origin items

### Context

While generating the item → crafting station link (`scripts/generate_bench_recipes.py`), 39 items were left over that have an entry in `DT_ItemRecipeDataTable_Common` (i.e. have a "recipe" with materials) but **don't match any real crafting station** (`bLegalInGame=True`, so this isn't cut game content).

Looking at each item's localized name/description (`DT_ItemNameText_Common` / `DT_ItemDescriptionText_Common`), they all point to the same pattern: they're obtained as **boss drops, event/NPC rewards, or automatic Pal unlocks** — the "recipe" in the DataTable exists only as the game's internal cost reference, but the player never actually crafts these items at a station.

Possible future feature: instead of showing a "recipe" for these items in the calculator, show their **special origin** (e.g. "Boss drop: Elizabee", "Reward from Gym Leader Zoe", "Automatically unlocked when the FlyingManta partner evolves"). Pending a decision on whether the calculator should cover this or only station-craftable items.
